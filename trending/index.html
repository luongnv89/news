Pick 1 · Web development / UI framework GitHub rank #18 of 19

solidjs/solid

TypeScript · License: MIT

What it does. A declarative JavaScript library for building user interfaces: no virtual DOM, templates compile to real DOM nodes that are updated through fine-grained reactive signals. Version 2.0 reached stable on 17 November, with patch releases 2.0.1 and 2.0.2 since.

Why it is interesting — editorial. The 2.0 release notes say async values now flow through the reactive graph: a computation can return a Promise or async iterator and downstream code handles it, with optimistic updates that roll back. The API also shrinks, dropping createResource, batch, startTransition and others, and development builds report reactive mistakes with a stable code and a suggested fix.

Caveat. This is a major version with removed APIs, so 1.x apps need the migration guide; 1.x stays on its own branch and npm tag. The two patch releases in two days show the stable line is still settling, and the claims about agent-friendly diagnostics are the maintainers' own.

Pick 2 · Web development / JavaScript library GitHub rank #11 of 19

jquery/jquery

JavaScript · License: MIT

What it does. The jQuery JavaScript library, which released 4.1.0, the first minor release of the 4.x line, together with 3.8.0 on 17 November.

Why it is interesting — editorial. Version 4.1.0 fixes a ReDoS in selector identifier matching that could hang a page, switches internal lookups to querySelectorAll, adds responseURL to jqXHR and serializes form-associated custom elements. For the many sites still on jQuery, the release post is also a clear signal: 3.8.0 is called a send-off, and the 3.x branch now gets only critical security and bug fixes.

Caveat. Teams still on 3.x face a 4.x upgrade with removed APIs; the project offers an upgrade guide and the jQuery Migrate plugin, but the 'minimal changes' expectation is the maintainers' estimate. Third-party CDNs may lag behind the official release.

Pick 3 · Developer tools / Python packaging GitHub rank #7 of 19

astral-sh/uv

Rust · License: Apache-2.0 or MIT

What it does. A Python package and project manager written in Rust: one tool meant to replace pip, pip-tools, pipx, poetry, pyenv, twine and virtualenv, with lockfiles, Python version management and pip-compatible commands.

Why it is interesting — editorial. Release 0.13.9 of 17 November is a practical maintenance step: it rejects wheels an index serves under a different package name, makes lockfiles smaller and faster to read, fixes lockfile checks that refused equivalent platform markers, and previews PEP 832 .venv redirect files. Small changes like these matter to anyone running uv in CI.

Caveat. uv is still on 0.x versions, so behaviour can change between releases; pin the version in CI. The README's 10-100x speed-up over pip is the maintainers' benchmark claim, which we did not measure, and the PEP 832 support is a preview feature.

Pick 4 · Automation / AI agents GitHub rank #17 of 19

n8n-io/n8n

TypeScript · License: Sustainable Use License (fair-code)

What it does. A workflow automation platform: a visual canvas combined with JavaScript or Python code to build multi-step workflows and AI agents, self-hosted with Docker or run in n8n's cloud.

Why it is interesting — editorial. First time on our list. n8n sits where many teams actually wire AI into their systems: the README lists 1500+ integrations, model switching between OpenAI, Anthropic, Google and open models, and human approval steps inside agent workflows. Self-hosting keeps the data on your own infrastructure.

Caveat. It is fair-code under the Sustainable Use License, not OSI open source: the license allows use only for your own internal business purposes or non-commercial use, and files marked .ee need a separate n8n Enterprise License. The integration and template counts are the company's figures, and the README's quick start pipes a remote script into a shell, which deserves a read before running.

Pick 5 · Backend platform / developer tools GitHub rank #12 of 19

appwrite/appwrite

TypeScript · License: BSD-3-Clause

What it does. An open-source backend platform: auth, databases, storage, functions, messaging, realtime and hosting in one product, available as a managed cloud or self-hosted with Docker.

Why it is interesting — editorial. First time on our list. Appwrite now presents itself as agent-first: an included MCP server lets coding agents operate on a live project, next to the usual client and server SDKs. Its 2.7.3 patch of 17 November rebuilds the base and executor images to clear their open vulnerability findings, with no schema changes.

Caveat. Letting a coding agent act on a live backend can change real data and permissions, so scope its access. The self-hosted installer mounts the Docker socket, which gives it control of the host's Docker, and the MCP and agent claims come from Appwrite's own README.

Pick 6 · AI agents / evaluation GitHub rank #5 of 19

NVIDIA/SkillEvaluator

Python · License: Apache-2.0

What it does. A framework for testing AI agent skills and plugins: quality and security checks, overlap detection, and runs with and without a skill to measure its effect on task results, with reusable CI templates.

Why it is interesting — editorial. Material change since our 16 November card, which covered version 0.9.0: v1.0.1, published on 18 November as the first complete 1.0 release, adds HarnessCheck, static checks for why a skill may be missed or truncated across Claude Code, Codex, Copilot CLI, Hermes, OpenClaw and OpenCode. It also adds NeMo Gym evaluations, JUnit output and offline pre-commit checks.

Caveat. HarnessCheck findings are advisory and based on versioned harness profiles, which can lag behind the agents themselves. The live evaluation tier needs model access and spending, and v1.0.0 was superseded within hours by v1.0.1, so pin the version.
