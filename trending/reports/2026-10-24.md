### 2. [NVIDIA/OpenShell](<https://github.com/NVIDIA/OpenShell>)

*AI agents / security · GitHub rank #4 of 8 · Rust · License: Apache-2.0*

**What it does:** A runtime that runs autonomous AI agents in isolated sandboxes and enforces a declared policy on what each one may access: files, system calls, network destinations and credentials, which are injected only into requests to approved endpoints.

**Why it is interesting (editorial):** *First time on our list. Agent sandboxing is one of the most practical open problems in agent tooling, and this project combines kernel-level enforcement with a check that flags risky new access before a policy change is approved. It ships a CLI, a local or Kubernetes gateway and SDKs for Python, TypeScript, Go and Rust; v0.1.5 shipped on 20 October.*

**Caveat:** Young 0.1.x software with breaking changes between minor releases: v0.1.5 renamed log files and changed Kubernetes template rules and the Go SDK API. It needs Linux, macOS on Apple Silicon or experimental WSL 2, plus Docker, Podman or host virtualization. Anonymous telemetry is on by default and can be disabled. The formal-verification and isolation claims are NVIDIA's; we did not test them, and the quickstart pipes a remote script into a shell, so review it first.

**Attention, not endorsement:** GitHub showed “1,119 stars today” as displayed for GitHub's daily window (not an audited rolling 24-hour count). Total stars: 18,934 at the metadata check.

### 3. [SnailSploit/Claude-Red](<https://github.com/SnailSploit/Claude-Red>)

*Security / AI agents · GitHub rank #6 of 8 · Python · License: MIT*

**What it does:** A library of 78 SKILL.md files in 23 categories that give Claude structured offensive-security methodology for specific attack surfaces, from SQL injection and OAuth abuse to container escape, Active Directory, wireless and exploit development.

**Why it is interesting (editorial):** *First time on our list. It shows how security teams are packaging tradecraft as agent skills that load on demand, and it is organized enough to be useful as a checklist library for authorized penetration tests, bug bounty triage, CTF practice and training. The v0.3.0 release in August expanded it from 37 to 78 skills.*

**Caveat:** For authorized work only: the project's own security policy limits it to scoped engagements, bug bounties with permission, CTFs and research, and warns that misuse may break computer-misuse laws. The skills are prompt text, not verified tooling, so the agent's output still needs expert review. Installing the whole library into your agent's skills folder makes it load automatically on matching topics; the repository also includes an install script and a Python converter, which we did not run.

**Attention, not endorsement:** GitHub showed “226 stars today” as displayed for GitHub's daily window (not an audited rolling 24-hour count). Total stars: 8,623 at the metadata check.

### 4. [OpenBMB/VoxCPM](<https://github.com/OpenBMB/VoxCPM>)

*AI / speech · GitHub rank #7 of 8 · Python · License: Apache-2.0*

**What it does:** VoxCPM2, an open text-to-speech model with about 2 billion parameters that generates speech in 30 languages, designs new voices from a text description, clones a voice from a short reference clip and outputs 48 kHz audio, with code and weights under Apache-2.0.

**Why it is interesting (editorial):** *First time on our list. Few open speech models combine multilingual output, voice design and controllable cloning under a license that allows commercial use. The project documents several ways to run it, including a GGUF port for CPU, Metal and Vulkan, and its May release 2.0.3 added a training-data validator and safer LoRA checkpoint loading.*

**Caveat:** The README lists Python 3.10-3.12, PyTorch 2.5+ and CUDA 12+ for the main package and about 8 GB of VRAM; its speed figures (real-time factor around 0.3 on an RTX 4090) and quality benchmarks are the maintainers' claims, which we did not reproduce. Voice cloning needs the speaker's rights and consent: the project forbids impersonation, fraud and disinformation and recommends labelling AI-generated audio. Running it downloads model weights from external hosts.

**Attention, not endorsement:** GitHub showed “150 stars today” as displayed for GitHub's daily window (not an audited rolling 24-hour count). Total stars: 40,362 at the metadata check.

### 5. [Renhuai123/ziwei-doushu](<https://github.com/Renhuai123/ziwei-doushu>)

*Culture / astrology software · GitHub rank #5 of 8 · TypeScript · License: MIT (code); CC BY 4.0 datasets; CC BY-NC-SA 4.0 quotations*

**What it does:** An open-source TypeScript engine and Next.js demo for drawing Zi Wei Dou Shu (Purple Star) charts, a traditional Chinese astrology system, following the teachings of Ni Haixia, plus a knowledge base of chart patterns, classical source texts and large chart datasets.

**Why it is interesting (editorial):** *First time on our list, and a change from developer tooling. It is a careful piece of cultural software engineering: the engine rejects impossible calendar dates, quotations are traced to timestamped lecture videos, and the 15 October dataset release (v4.0) provides 8.8 million deterministically generated readings, built without AI, for 1950-2026 under CC BY 4.0.*

**Caveat:** This is a divination tradition, not a scientifically validated predictive method; read the charts as cultural content. The licensing is split: code MIT, datasets CC BY 4.0, and the transcribed Ni Haixia quotations CC BY-NC-SA 4.0 (no commercial use). The open version leaves out the interpretation library, AI readings and backend that power the author's commercial site. Documentation is mainly Chinese, with a shorter English README, and the full dataset is about 57 GB uncompressed.

**Attention, not endorsement:** GitHub showed “546 stars today” as displayed for GitHub's daily window (not an audited rolling 24-hour count). Total stars: 7,018 at the metadata check.
