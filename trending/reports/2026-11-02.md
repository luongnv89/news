## Picks

### 1. [beenuar/AiSOC](<https://github.com/beenuar/AiSOC>)

*Security / SOC automation · GitHub rank #10 of 17 · Python · License: MIT*

**What it does:** A **self-hosted AI security operations centre**. It takes in security telemetry from pushed events or 90 data connectors (Splunk, Sentinel, Elastic, CrowdStrike, Okta, AWS and others), runs detection rules, groups alerts into incidents and has an AI agent investigate each one. Every prompt, tool call and verdict goes into an Investigation Ledger that can be exported as a signed evidence bundle, and response actions are proposed for a human to approve.

**Why it is interesting (editorial):** *First time on our list, and the only security project on today's list. Its README is unusually candid: it separates the 2,538 rules it has seen fire from the 7,023 on disk, labels synthetic demo data, and says **no hosted model provider has ever been exercised**. Response playbooks preview by default and **need three separate opt-ins plus a human approver**, a sensible default for agents near production systems.*

**Caveat:** The core profile needs Docker with about 8 GB of memory and 20 GB of disk and downloads a \~2 GB local model (Llama 3.2 3B) that is, in the README's words, not a frontier model. It is **largely one maintainer's work** (about 1,050 commits, far more than any other person) and reached v21.0.0 in six months, with a breaking change to alert grouping in that release. Its benchmark figures are the maintainer's own, and it is **not a drop-in SIEM replacement**. For authorized monitoring only; we did not run it.

**Attention, not endorsement:** GitHub showed “446 stars today” as displayed for GitHub's daily window (not an audited rolling 24-hour count). Total stars: 6,413 at the metadata check.

### 2. [thedotmack/claude-mem](<https://github.com/thedotmack/claude-mem>)

*AI agents / memory plugin · GitHub rank #1 of 17 · TypeScript · License: Apache-2.0*

**What it does:** A **persistent memory plugin for coding agents** (Claude Code, Codex, OpenCode, Gemini and others). Hooks record what the agent does in a session, a model compresses it into summaries kept in local SQLite with vector search, and later sessions get relevant context back. An optional cmem.ai cloud service adds a hosted summarizer and sync.

**Why it is interesting (editorial):** *Back on our list because of a material privacy fix, not its rank. Release v15.8.3 (2 November) states that **the browser setup opened by its installer uploaded the last 30 days of prompts** from local agent histories, with session IDs, project names, folder paths and timestamps, to cmem.ai without asking, in every version since v15.2.0. The fix makes the scan local-only until you tick which tools to upload, and adds a "Keep everything local" choice. Our 30 October card called cloud sync optional; **this behaviour was not visible in the README we read then**.*

**Caveat:** The release notes say **prompts already uploaded are not removed by this update**, and server-side handling at cmem.ai is outside the fix; the issue that reported it (5176) was still open when we checked. Anyone who ran the installer's browser setup between v15.2.0 and v15.8.2 should assume that history was sent. It still **captures everything your agent does**, so secrets in tool output can reach its database. We did not install or run it.

**Attention, not endorsement:** GitHub showed “1,526 stars today” as displayed for GitHub's daily window (not an audited rolling 24-hour count). Total stars: 109,805 at the metadata check.

### 3. [cjpais/Handy](<https://github.com/cjpais/Handy>)

*Desktop utilities / speech-to-text · GitHub rank #7 of 17 · Rust · License: MIT*

**What it does:** A **free, offline speech-to-text app** for Windows, macOS and Linux. Hold or tap a shortcut, speak, and the transcription is pasted into whatever app has focus. Silence is filtered with Silero voice detection, and you choose the speech model: Whisper (Small to Large, with GPU acceleration where available) or the CPU-friendly Parakeet V3 with automatic language detection.

**Why it is interesting (editorial):** *First time on our list. Dictation is an accessibility tool that is usually sold as a subscription or sent to a cloud service; Handy **keeps audio on your computer** and is MIT-licensed, with signed releases you can check with minisign and a CLI for controlling a running instance. It is an established project (created February 2025, v0.9.8 on 3 October) with many outside contributors in its release notes. At rank 12, anomalyco/hex is a newer app doing the same job.*

**Caveat:** Still pre-1.0, and the README lists known issues: Bluetooth headset microphones can degrade audio on macOS, and fn/Globe-key shortcuts work only on Apple keyboards. It needs **microphone and accessibility permissions** to paste into other apps, and the app downloads its speech models, which can be large, before it can transcribe (a manual route exists for restricted networks). The Homebrew and winget packages are not maintained by the Handy developers. Transcription accuracy depends on the model you pick; we did not test it.

**Attention, not endorsement:** GitHub showed “339 stars today” as displayed for GitHub's daily window (not an audited rolling 24-hour count). Total stars: 36,828 at the metadata check.

### 4. [FlashML-org/FreeToken](<https://github.com/FlashML-org/FreeToken>)

*AI infrastructure / local model serving · GitHub rank #16 of 17 · Python · License: Apache-2.0*

**What it does:** An **engine for serving large Mixture-of-Experts models on consumer GPUs**. It splits work between the GPU and CPU, keeps recently used experts cached in VRAM and reuses saved context when an agent edits its history, and offers OpenAI- and Anthropic-compatible APIs so coding agents such as Codex, Claude Code and OpenCode can use a local model. A desktop app for Windows and Linux is offered from its website.

**Why it is interesting (editorial):** *First time on our list. It comes with an arXiv paper whose authors include Ion Stoica, Matei Zaharia, Song Han and Kurt Keutzer, and it targets a real pain point: **running very large open-weight MoE models on one gaming PC** instead of a server. Releases are frequent; v0.2.1 (26 October) added image input for GGUF models and more model families.*

**Caveat:** The README's "290B+ models at blistering interactive speeds" is **a maintainer claim we did not measure**. The documented install needs Linux x86\_64, an NVIDIA GPU (RTX 30 series or newer) with driver r580+ and a CUDA 13 toolkit with nvcc, since kernels are compiled on first use; AMD support is marked work in progress. Model weights are large downloads with their own licences, and the docs include a guide for repairing old checkpoints in its own weight format. We did not run it.

**Attention, not endorsement:** GitHub showed “242 stars today” as displayed for GitHub's daily window (not an audited rolling 24-hour count). Total stars: 15,592 at the metadata check.

### 5. [kornia/kornia](<https://github.com/kornia/kornia>)

*Developer tools / computer vision · GitHub rank #9 of 17 · Python · License: Apache-2.0*

**What it does:** A **differentiable computer vision library for PyTorch**: image filtering, augmentations, geometry, feature matching (SIFT, RANSAC) that run batched on the GPU and pass gradients through, so they can sit inside a training pipeline.

**Why it is interesting (editorial):** *First time on our list. Version 0.9.0 (23 October) followed what the maintainers describe as a three-month audit for silent bugs, crashes and slow-downs, with 995 community pull requests merged and **models that never worked removed**. The README now says when not to use it (one fixed blur or resize is just as easy in plain PyTorch) and publishes benchmark set-ups, and the release adds an index for coding agents.*

**Caveat:** The speed-ups in the release notes (for example 16x faster Gaussian blur on Apple CPUs, faster than OpenCV on CUDA) are **maintainer benchmarks we did not reproduce**; the notes themselves say it is about 4x slower than OpenCV on CPU. Removing broken models such as SAM3 can break code that imported them, so **pin the version and read the changelog** before upgrading. It needs PyTorch, which is a large install.

### 6. [hyprwm/Hyprland](<https://github.com/hyprwm/Hyprland>)

*Desktop / Linux window manager · GitHub rank #17 of 17 · C++ · License: BSD-3-Clause*

**What it does:** An **independent tiling Wayland compositor for Linux** (not built on wlroots, KWin or Mutter) with animations, blur, plugins, socket IPC and dwindle, master and scrolling layouts. Its configuration reloads as soon as you save it, and recent releases move it to a Lua configuration API.

**Why it is interesting (editorial):** *First time on our list, though it has been around since 2022. Version 0.57.0 (28 October) is a large release: Lua API additions such as reload\_config() and device listing, new window rules, pointer transforms, a window wobble effect and many fixes. It is a mature, actively developed project **for people who want to script their desktop**.*

**Caveat:** Linux only, and it moves fast. The 0.57.0 notes list **removal of legacy config support**, a deprecated option, two options moved to a new category and new deprecation notices, so **check your config and plugins before upgrading**. A tiling compositor takes time to set up compared with a ready-made desktop, and BSD-3-Clause licensing covers the compositor, not every plugin. We did not install it.

**Attention, not endorsement:** GitHub showed “38 stars today” as displayed for GitHub's daily window (not an audited rolling 24-hour count). Total stars: 39,510 at the metadata check.
